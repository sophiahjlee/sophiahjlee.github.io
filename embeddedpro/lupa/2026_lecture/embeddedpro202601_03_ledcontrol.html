📋 주요내용
  • LED CONTROL Manager 1.0은 Application에서 LED 배치 정보를 직접 설정하고, Manager와 HAL이 단순 연결 구조였으나 2.0에서는 배치 정보가 디바이스 트리로 이동하고 구조가 간소화됨.
  • 2.0 구조에서는 핵심 제어 로직이 HAL에서 Manager로 이동하여, HAL은 Driver와 Manager를 연결하는 역할만 담당하며, Driver 레이어가 추가되어 신규 디바이스 확장이 용이해짐.
  • LED CONTROL Manager 2.0에서는 MATRIX LED와 DIRECT LED를 구분하여 관리하며, 각 LED 제어 API(on, off, brightness, color 등)는 HAL을 통해 Manager에 등록되고, Manager가 이를 통해 Driver를 제어함.
  • 디바이스 트리(device tree)에 LED 맵 정보를 정의함으로써, Application에서 직접 맵을 관리하지 않고 시스템적으로 일관된 LED 제어가 가능해짐.
  • 기존 구조의 한계(여러 LED 타입 구분 불가, 확장성 부족 등)를 개선하여 다양한 LED 디바이스와 제어 방식(RGB, GPIO 등)에 유연하게 대응할 수 있도록 구조가 변경됨.

📋 주요내용
  • LUPA에서는 shell 모듈을 통해 framework나 device driver에서 LED CONTROL MANAGER의 API를 호출하여 LED를 제어할 수 있으며, 앱을 거치지 않고 CLI로 직접 제어가 가능하다.

  • LED CONTROL framework는 1.0과 2.0 API 버전을 모두 지원하여 다양한 device tree 구조와 호환성을 제공한다.

  • Encoder 이벤트는 knob 부분에서 발생하며, input manager에서 처리된다.
