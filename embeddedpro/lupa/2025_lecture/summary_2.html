📋 주요내용

  • LUPA 플랫폼은 가전 제품(세탁기·오븐·에어콘 등)에 탑재되는 임베디드 OS로, 빨간 점선 안쪽이 플랫폼 공통역량이며 그 바깥은 사업부 개발 영역이다
  • 플랫폼과 앱이 분리된 구조로, SOTA(앱 업데이트)와 FOTA(플랫폼 업데이트)를 독립적으로 배포할 수 있다
  • 버전 이력: 1.1 LTS(세탁기 첫 탑재, 장기 지원), 1.2(NAND 플래시 · IT칩 지원 추가), 2.0(DQC2 · Cortex-M85 지원)
  • 메인 브랜치는 익일 반영되고, 1.1/1.2 안정 브랜치는 TSC 리뷰와 형상관리팀 검증을 거쳐 약 2주 소요된다

  • LUPA IPC 메커니즘(Setting, Event, Message Queue, Property)의 특성과 사용법을 이해한다

📋 주요내용

  • pthread로 자식 스레드 생성 가능(최대 4개); 스레드 속성(스택 크기, 우선순위)을 설정한 뒤 pthread_create 호출
  • 이벤트(Event): 1:N 단방향 브로드캐스트, create → connect → receive(timeout 설정 가능) → destroy 흐름
  • 메시지 큐(MQ): 양방향 가능하지만 보내는 쪽 사이즈 ≤ 큐 정의 사이즈 규칙 필수; 수신 측이 처리를 못하면 큐 full 장애 발생
  • 프로퍼티(Property): 공유 메모리 기반의 IPC로, ID 정의 시 타입·크기·방향(READ/WRITE/RW)을 지정
  • 프로퍼티 서버는 register_property로 저장소를 생성하고 update_property_value로 값을 갱신한다
  • 클라이언트 앱은 get_property 또는 subscribe_property_with_event로 값 변경 시 자동 콜백을 받을 수 있다
  • 실무에서는 대부분 Property API를 가장 많이 활용하며, 사업부에서도 공통 헤더에 프로퍼티 ID를 정의하여 공유한다
